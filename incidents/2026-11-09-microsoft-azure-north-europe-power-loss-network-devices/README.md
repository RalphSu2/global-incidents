# Microsoft Azure — North Europe 区域多台网络设备断电

> **分级：C 级** · **厂商未发布技术报告**。Azure 仅在门户内推送了 Service Issue 通知，因未达其公开 PIR 门槛（"Scenario 1"：多服务 + 多区域的广泛影响），本次**不发布公开 PIR**。

## 一句话结论

North Europe 区域多台网络设备遭遇断电，机器不可达、集群延迟与丢包，持续约 3.5 小时；同一小时内 23 家服务报告异常。**厂商未披露是哪个环节的电力故障，也未公开任何复盘。**

## 根因（官方口径）

**厂商未发布技术报告，未披露根因。**

已知的唯一官方表述是"多台网络设备遭遇断电（power loss of multiple network devices）"。**没有说明**：断电发生在哪个设施环节、为何多台设备同时失电、为何没有冗余接管、影响范围如何界定。

## 为什么没有 PIR

Azure 的公开 PIR 规则是：仅当事件达到 **"Scenario 1"**（多服务 + 多区域的广泛影响）才对外发布 PIR；其余事件只定向通知受影响客户。本次 North Europe 单区域断电未达该门槛。

> 解读：这构成一个结构性问题 —— **最重要的故障往往拿到最少的文档**。用户无法从公开渠道了解该区域的冗余到底是怎么失效的。

## 技术要点

> 解读：以下为我的推断，**厂商未确认**。

**1. "多台网络设备"同时断电指向设施级问题**
单台设备故障不会造成"多台同时断电"。可能路径是机柜/机房级供电故障，或同一供配电支路下的设备集体失电。

**2. 网络设备没有电池后备是常见的架构缺口**
服务器有 UPS，但网络汇聚/核心设备是否同样有后备供电，在各云厂商之间差别很大。

**3. 23 家服务在同一小时内报告异常，说明依赖高度集中**
区域级网络是公共底座，一旦失效会同时打掉计算、存储、数据库、PaaS 各层。

## 与我们相关的启示

> 解读：以下为我的分析。

**① 单区域部署的风险被低估了** —— 这起事件没有任何厂商报告，意味着客户连"我的架构该怎么改"都无从判断。**跨区域部署的理由不需要等报告。**

**② 网络设备的供电冗余要单独核查** —— 不要假定"机房有 UPS"就等于"网络设备有后备"。

**③ 对 Azure 客户而言，PIR 不是可期待的权利** —— 只有 Scenario 1 才有。要把"拿不到复盘"当作常态来做容量与容灾规划。
